FileVPS engine

FileVPS vs typical cloud VM

Not a classic KVM VM. Guests share host OS base and kernel. CPU, RAM, and GPU are shared with per-VPS limits. RAM optimized with cgroup + optional worker ZRAM.

Typical cloud VM
  • Own guest kernel per VM
  • Full guest OS disk copy
  • Heavy idle RAM (often 100 to 500+ MB)
  • Swap usually on disk (slow)
  • GPU often needs passthrough
CloFix FileVPS (shared)
  • Share kernel - no second guest kernel
  • Share OS base - OverlayFS + writable layer
  • Share CPU / RAM - cgroup v2 limits
  • Share GPU - on capable workers
  • ~1.7s ready · ~1.6 to 2.6 MB idle
RAM optimize + ZRAM
  • Per-VPS RAM / swap limits (cgroup)
  • Tiny idle footprint vs classic VMs
  • Worker ZRAM - compressed RAM swap
  • Faster than disk swap under pressure
  • More VPS density on the same host RAM

ZRAM is host-wide worker capacity (CLOFIX_ZRAM_MB). Isolation: namespaces, seccomp, cgroup, Protection Mode - not hardware hypervisor isolation.

Default security

Protection Mode

Use Protection Mode on FileVPS. Guest root stays read-only by default. Safer production with less risk of accidental or malicious system changes.

What you get
  • On by default for new FileVPS
  • Persistent guest root stays read-only
  • `/run`, `/tmp`, `/var/log` stay temporary
  • `apt update` still works for indexes
  • Works with Security Modes templates
Benefits if you use Protection Mode
  • Harder for attackers to change system files
  • Less risk of accidental OS breakage
  • Safer default for public websites
  • Clear change window: turn off only to install packages, then turn back on
  • Pairs with modes: Standard, Hardened, Lockdown, Maintenance, Web Block
  • Processes and network keep running while disk stays locked
