How to use secrets
Create a secret in Vault first. Then pick one path below. IAM keys need secrets:read for runtime fetch; console sync/create needs secrets:manage.


        

          Ref formats (Jobs / Docker / CKS form)
          
sec:sec-a1b2c3d4e5f60708
{{`{{secret:db-password}}`}}

        


        

          
1. FileVPS

          
Guest apps call the admin API at runtime. Create an IAM access key (Security → IAM → Access keys) with secrets:read.

          
    
            
  1. Create vault secret (example name db-password).
    2. 
            
  2. Generate IAM bearer CFX….secret.
    3. 
            
  3. From inside the VPS (or any host that can reach the admin URL), fetch the value.
    4. 
          

          
By name

          
export CLOFIX_IAM_BEARER='CFX….secret'
curl -sS -H "Authorization: Bearer $CLOFIX_IAM_BEARER" \
  http://localhost:8080/api/secrets/by-name/db-password/value

          
By id

          
curl -sS -H "Authorization: Bearer $CLOFIX_IAM_BEARER" \
  http://localhost:8080/api/secrets/sec-a1b2c3d4e5f60708/value

          
Example response

          
{"id":"sec-a1b2c3d4e5f60708","name":"db-password","type":"string","value":"s3cret!","version":1}

          
Shell: export into env

          
export DB_PASS="$(curl -sS -H "Authorization: Bearer $CLOFIX_IAM_BEARER" \
  http://localhost:8080/api/secrets/by-name/db-password/value | jq -r .value)"
./my-app

        


        

          
2. Docker

          
Two options: inject at start (ref in env), or call the runtime API from the container.

          
A. Inject (recommended) - Applications → Docker → Environment JSON. CloFix resolves refs when the container job is queued.

          
{
  "MODE": "production",
  "DB_PASS": "sec:sec-a1b2c3d4e5f60708",
  "API_TOKEN": "{{`{{secret:db-password}}`}}"
}

          
B. Runtime fetch inside container - same curl as FileVPS; admin host must be reachable from the container network.

          
curl -sS -H "Authorization: Bearer $CLOFIX_IAM_BEARER" \
  http://localhost:8080/api/secrets/by-name/db-password/value

        


        

          
3. Applications · Jobs & Functions

          
Put refs in the job Environment JSON (or in Secrets JSON). Values are resolved when the run starts.

          
    
            
  1. Create vault secret db-password.
    2. 
            
  2. Open Applications → edit Job/Function → Environment.
    3. 
            
  3. Run the job; the process sees the real plaintext.
    4. 
          

          
Environment JSON example

          
{
  "MODE": "batch",
  "DB_PASS": "{{`{{secret:db-password}}`}}"
}

          
What the job process receives

          
MODE=batch
DB_PASS=s3cret!

        


        

          
4. CKS (Kubernetes)

          
Prefer a native Kubernetes Secret, then mount it into pods. Or call the runtime API from a pod if the admin URL is reachable.


          
A. Sync from Vault

          
    
            
  1. Open Vault → row actions → Sync to CKS.
    2. 
            
  2. Pick cluster, namespace (e.g. default), Secret name (e.g. db-secret).
    3. 
            
  3. String secrets become key value; key/value secrets map each key.
    4. 
          


          
B. Create Secret in CKS UI with refs - CKS → Resources → Secret → data lines:

          
USERNAME=demo
PASSWORD=sec:sec-a1b2c3d4e5f60708
TOKEN={{`{{secret:db-password}}`}}


          
C. Use in a Deployment (envFrom)

          
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  template:
    spec:
      containers:
      - name: api
        image: my-api:1.0
        envFrom:
        - secretRef:
            name: db-secret


          
D. Single key

          
env:
- name: DB_PASS
  valueFrom:
    secretKeyRef:
      name: db-secret
      key: value


          
E. Runtime API from a pod

          
curl -sS -H "Authorization: Bearer $CLOFIX_IAM_BEARER" \
  http://host.docker.internal:8080/api/secrets/by-name/db-password/value
